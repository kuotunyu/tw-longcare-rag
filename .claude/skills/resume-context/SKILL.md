# 恢復專案脈絡

## 什麼時候用

- 隔數天/數週回到專案的第一個動作
- 使用者問「做到哪了」「接下來要幹嘛」
- 新 session 開始且不確定現況時

## 步驟（全程唯讀，不改任何檔案）

1. 讀 `PROGRESS.md` 快速回憶區（上次收工日期、現在做到哪、下一步、已知坑）
2. `git log --oneline -10` + `git tag`（tag `phase-N` 一眼定位進度）；`git status --short` 看有無未收尾的工作區變更
3. 環境健檢：`uv run pytest -q`（壞了優先回報，不硬修）
4. 資源健檢（要跑地端模型才需要）：`nvidia-smi` 看 VRAM、`ollama list` 看模型在不在
5. 對照 `PLAN.md` 當前 Phase 的 DoD 清單，判斷缺什麼
6. 回報：**現況摘要（3 行內）+ 已知坑提醒 + 建議的第一步（具體到指令/檔案）**，等作者確認再動工

## 注意

- 這支 skill 只診斷不治療：發現 PROGRESS 與實際不符（例如宣稱的測試沒過）→ 如實回報差異，修正動作等確認
- 工作區有未 commit 變更時，先弄清楚是誰留的、為什麼，不要順手 commit 或丟棄

## 完成檢查

- [ ] 回報含：上次收工日期、當前 Phase 與 DoD 缺口、建議第一步
- [ ] 沒有修改任何檔案
